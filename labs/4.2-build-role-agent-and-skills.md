# 4.2 · ใช้ Role Agent ที่เตรียมไว้: แยกบทบาทออกจากวิธีทำงาน (12 นาที)

**สิ่งที่จะฝึก:** อ่านไฟล์ `.github/agents/<role>.agent.md` ที่เตรียมไว้, ตรวจว่า `tools:` เหลือเฉพาะเครื่องมือที่ต้องใช้จริงโดยตัด `execute` (Terminal) ออก, และรันภารกิจ Sprint 2 ที่ **คุณเลือก Agent → แล้ว Agent เลือกใช้ Skill เอง** ในคำขอเดียว

---

## 1. เปิดอ่าน Custom Agent ประจำสายงานที่เตรียมไว้ใน `.github/agents/` (4 นาที)

เราเตรียม Custom Agent ทั้ง 3 สายงานไว้ใน `.github/agents/` ให้แล้ว **ไม่ต้องคัดลอกไฟล์หรือรันคำสั่งติดตั้ง** เลือกเปิดอ่านไฟล์ตามสายงานของคุณ (**BA**, **QA** หรือ **Dev**) และเทียบกับ [Review Card](design-card.md) จากข้อ 4.1 ส่วน Agent สายงานอื่นพร้อมใช้ฝึกส่งไม้ต่อ Handoffs ในข้อ 4.3:

| สายงาน | ไฟล์ที่เตรียมไว้ | `tools:` ใน Frontmatter | Skill ที่ Agent ใช้จาก Body |
|---|---|---|---|
| **BA** | [`.github/agents/ba-analyst.agent.md`](../.github/agents/ba-analyst.agent.md) | `['read', 'search', 'edit']` *(ไม่มี `execute`!)* | `['cr-spec-writer']` |
| **QA** | [`.github/agents/qa-inspector.agent.md`](../.github/agents/qa-inspector.agent.md) | `['read', 'search', 'edit']` *(ไม่มี `execute`!)* | `['test-matrix-designer']` |
| **Dev** | [`.github/agents/dev-builder.agent.md`](../.github/agents/dev-builder.agent.md) | `['read', 'search', 'edit']` *(ไม่มี `execute`!)* | `['ui-implementer']` |

> **เปิดอ่านไฟล์ `.github/agents/<role>.agent.md` ของคุณแล้วตรวจจุดสำคัญเหล่านี้:**
> 1. **`name` & `description`:** ชื่อและคำอธิบายที่แสดงใน Agent dropdown (และใช้ให้ Agent ตัวอื่นตัดสินใจเมื่อเรียกเป็น Subagent)
> 2. **`tools: ['read', 'search', 'edit']`:** อนุญาตให้อ่าน ค้นหา และเขียนไฟล์ผลลัพธ์ แต่ **ตัด `execute` (Terminal), `web` และ `todo` ออก**
> 3. **Skill ใน Body:** มีลิงก์ไปยัง `SKILL.md` และสั่งให้อ่าน Checklist / Template ก่อนทำงาน
> 4. **`handoffs:`:** ปุ่มส่งไม้ต่อให้บทบาทถัดไปพร้อม `send: true` (ส่งคำขอทันทีเมื่อคลิก)
> 5. **Body (ข้อความด้านล่าง `---`):** กำหนดบทบาท ขอบเขตงาน และสั่งให้หยุด (`STOP`) พร้อมสรุปรายงานเมื่อเขียนไฟล์เสร็จ

ตั้ง **Session Target เป็น Local** ก่อนเลือก Agent ใน New Chat

### วิธีใช้ Skill จาก Local Agent

ฟิลด์ `skills:` ไม่อยู่ใน Frontmatter ของ Local Agent ดังนั้น Agent แต่ละตัวมีคำสั่งใน Body ให้อ่าน Skill จาก Markdown link และทำตาม Checklist / Template ที่ลิงก์อยู่ใน Skill.

ตัวอย่างจาก `release-auditor.agent.md` (ลิงก์สัมพันธ์กับตำแหน่งไฟล์ Agent):

```markdown
ก่อนเริ่มตรวจ ให้อ่านและทำตาม [Skill release-gate-audit](../skills/release-gate-audit/SKILL.md)
รวมถึงเกณฑ์ตรวจที่ลิงก์ไว้ใน Skill นี้
```

เลือก Agent ที่เตรียมไว้แล้วส่งโจทย์ได้เลย ตรวจหลักฐานการอ่าน Skill / ไฟล์ประกอบตามขั้นตรวจผลลัพธ์ด้านล่าง หากไม่อ่าน ให้แนบ `SKILL.md` ของบทบาทในแชตแล้วส่งว่า **“อ่านและทำตาม Skill ที่แนบก่อนทำโจทย์เดิม”**

### งานนี้ Skill ก็ทำได้ แล้วเลือก Role Agent เพื่ออะไร?

| สิ่งที่ต้องการ | อยู่ที่ไหน / เหตุผล |
|---|---|
| BA รู้วิธีเขียน Spec, QA รู้วิธีออกแบบเคส, Dev รู้วิธีแก้ตาม Policy | **Skill** เก็บขั้นตอนและแม่แบบ ใช้กับ Default Agent ก็ทำงานเหล่านี้ได้ |
| เลือกบทบาท BA / QA / Dev ที่ทีมเตรียมไว้ ไม่ต้องกำหนดบทบาทใหม่ในทุกแชต | **Agent Body** เก็บหน้าที่และจุดส่งต่องาน; ยังเป็นคำสั่งให้โมเดลทำตาม ไม่ใช่การบังคับ |
| ให้เขียนผลงานได้ แต่ไม่ต้องการ Terminal ในงานนี้ | **Agent `tools:`** ระบุ `read`, `search`, `edit` โดยไม่ระบุ `execute`; ตรวจการกรองจริงในข้อ 4.4 |
| ให้ผู้ตรวจอ่านอย่างเดียว ต่างจากผู้สร้างที่ต้องเขียนไฟล์ | ใช้ **`release-auditor` อีกโปรไฟล์หนึ่ง** ที่ไม่มี `edit` ในรายการ แทนแค่บอกผู้สร้างว่า “เปลี่ยนไปเป็นผู้ตรวจ” ในแชตเดิม |

**ไม่ใช่ทุกบทบาทจำเป็นต้องมี Agent แยก:** BA / QA / Dev ในแล็บนี้มี `tools:` เหมือนกัน ประโยชน์ของการแยกสามตัวคือเลือกหน้าที่และการส่งต่อที่ทีมใช้ซ้ำ ไม่ใช่เพราะ Skill ทำเอกสารหรือแก้โค้ดไม่ได้ ถ้าไม่ต้องการโปรไฟล์เหล่านี้ ใช้ Default Agent + Role Skill ได้

## 3. ทำภารกิจด้วย `Role Agent + Role Skill` (7 นาที)

เปิด **New Chat** → คลิก Agent dropdown แล้วเลือก Agent ประจำสายงานของคุณ (**`ba-analyst`**, **`qa-inspector`** หรือ **`dev-builder`**) แล้วส่งคำขอด้านล่างตามภารกิจที่เลือก:

### สาย BA · เลือก Agent `ba-analyst` (ตรวจการใช้ Skill `cr-spec-writer`)

- **ถ้าเลือก `CR-201` (Project หมูกระทะ):**
  ```text
  ช่วยจัดทำ Change Request Specification สำหรับ CR-201
  ```
- **ถ้าเลือก `CR-202` (Project ชานมหวานร้อย):**
  ```text
  ช่วยจัดทำ Change Request Specification สำหรับ CR-202
  ```

### สาย QA · เลือก Agent `qa-inspector` (ตรวจการใช้ Skill `test-matrix-designer`)

- **ถ้าเลือก `CR-201` (Project หมูกระทะ):**
  ```text
  ช่วยออกแบบ Test Cases และบันทึกบั๊กสำหรับ CR-201
  ```
- **ถ้าเลือก `CR-202` (Project ชานมหวานร้อย):**
  ```text
  ช่วยออกแบบ Test Cases และบันทึกบั๊กสำหรับ CR-202
  ```

### สาย Dev · เลือก Agent `dev-builder` (ตรวจการใช้ Skill `ui-implementer`)

- **ถ้าเลือก `CR-201` (Project หมูกระทะ):**
  ```text
  ช่วยแก้โค้ดสำหรับ CR-201 ให้ครบตาม Acceptance Criteria
  ```
- **ถ้าเลือก `CR-202` (Project ชานมหวานร้อย):**
  ```text
  ช่วยแก้โค้ดสำหรับ CR-202 ให้ครบตาม Acceptance Criteria
  ```

**ตรวจผลลัพธ์ทีละด้าน:**

1. **Skill ช่วยทำงานอย่างไร:** ดูประวัติการทำงานว่า Agent เปิดอ่าน `SKILL.md` และไฟล์ประกอบที่ Skill อ้างถึงหรือไม่ จากนั้นชี้ให้เห็นว่าขั้นตอนหรือแม่แบบจากไฟล์เหล่านั้นอยู่ตรงไหนในผลงาน 
2. **Role Agent ตั้งค่าอะไรไว้:** ตรวจว่าเลือก Agent ถูกตัว และอ่านค่า `tools:` ในไฟล์ Agent เพื่อดูว่าตั้งค่าให้ใช้เครื่องมือใดบ้าง และให้ดูด้วยว่า Agent หยุดตามคำสั่งและไม่ทำงานต่อเกินขอบเขตหรือไม่
3. **ถ้าอยู่สาย Dev ให้ทดสอบหน้าเว็บ:** เปิด `ui/preview.html` ใน Browser แล้วทดสอบตามภารกิจที่เลือก:
   - `CR-201`: ลองกรอกจำนวนลูกค้า 2, 4, 8 และ 15 คน
   - `CR-202`: ลองใช้โค้ด `SWEET11` กับโซฟา `Lolito -50%` และกรองหมวด `Lighting`

   จากนั้นตรวจว่าผลที่ได้ตรงกับ Acceptance Criteria ของ CR หรือไม่
