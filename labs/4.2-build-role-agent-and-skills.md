# 4.2 · ใช้ Role Agent ที่เตรียมไว้: แยกบทบาทออกจากวิธีทำงาน (12 นาที)

**สิ่งที่จะฝึก:** อ่านไฟล์ `.github/agents/<role>.agent.md` ที่เตรียมไว้ตามโครงสร้าง Agent Anatomy (สไลด์ 6), ตรวจว่า `tools:` เหลือเฉพาะเครื่องมือที่ต้องใช้จริงโดยตัด `execute` (Terminal) ออก (สไลด์ 8), และรันภารกิจ Sprint 2 ที่ **คุณเลือก Agent → แล้ว Agent เลือกใช้ Skill เอง** ในคำขอเดียว (สไลด์ 5 & 7)

## 1. เปิดอ่าน Custom Agent ประจำสายงานที่เตรียมไว้ใน `.github/agents/` (4 นาที)

เราเตรียม Custom Agent ทั้ง 3 สายงานไว้ใน `.github/agents/` ให้แล้ว **ไม่ต้องคัดลอกไฟล์หรือรันคำสั่งติดตั้ง** เลือกเปิดอ่านไฟล์ตามสายงานของคุณ (**BA**, **QA** หรือ **Dev**) และเทียบกับ [Review Card](design-card.md) จากข้อ 4.1 ส่วน Agent สายงานอื่นพร้อมใช้ฝึกส่งไม้ต่อ Handoffs ในข้อ 4.4:

| สายงาน | ไฟล์ที่เตรียมไว้ | `tools:` ใน Frontmatter | `skills:` ที่ผูกไว้ |
|---|---|---|---|
| **BA** | [`.github/agents/ba-analyst.agent.md`](../.github/agents/ba-analyst.agent.md) | `['read', 'search', 'edit']` *(ไม่มี `execute`!)* | `['cr-spec-writer']` |
| **QA** | [`.github/agents/qa-inspector.agent.md`](../.github/agents/qa-inspector.agent.md) | `['read', 'search', 'edit']` *(ไม่มี `execute`!)* | `['test-matrix-designer']` |
| **Dev** | [`.github/agents/dev-builder.agent.md`](../.github/agents/dev-builder.agent.md) | `['read', 'search', 'edit']` *(ไม่มี `execute`!)* | `['ui-implementer']` |

> **เปิดอ่านไฟล์ `.github/agents/<role>.agent.md` ของคุณแล้วเช็กเทียบกับสไลด์ 6 (Agent Anatomy):**
> 1. **`name` & `description`:** ชื่อและคำอธิบายที่แสดงใน Agent dropdown (และใช้ให้ Agent ตัวอื่นตัดสินใจเมื่อเรียกเป็น Subagent)
> 2. **`tools: ['read', 'search', 'edit']`:** อนุญาตให้อ่าน ค้นหา และเขียนไฟล์ผลลัพธ์ แต่ **ตัด `execute` (Terminal), `web` และ `todo` ออก**
> 3. **`skills:` (Copilot harness):** ระบุชื่อ Skill ที่โหลดเข้าบริบท; **Local ไม่ใช้ค่านี้** จึงมีคำสั่งให้อ่าน `SKILL.md` ผ่านลิงก์ใน Body ด้วย
> 4. **`handoffs:`:** ปุ่มส่งไม้ต่อให้บทบาทถัดไปพร้อม `send: false` (ทำงานใน Local harness ตามสไลด์ 12)
> 5. **Body (ข้อความด้านล่าง `---`):** กำหนดบทบาท น้ำเสียงมืออาชีพ (ที่ชนะกฎซึนเดเระใน `copilot-instructions.md` ตามสไลด์ 7) และสั่งให้หยุด (`STOP`) พร้อมสรุปรายงานเมื่อเขียนไฟล์เสร็จ

### ถ้าใช้ Local แล้วเห็น `Attribute 'skills' is ignored when running locally in VS Code.`

**เป็นคำเตือนที่คาดไว้ ไม่ได้แปลว่า Local ใช้ Skill ไม่ได้** เราเก็บ `skills:` ไว้ให้เห็นการตั้งค่าของ Copilot harness และใช้ไฟล์ Skill เดียวกันทั้งสอง Harness:

| Harness | Agent ใช้ Skill ได้อย่างไร? |
|---|---|
| **Copilot** | `skills:` ระบุ Skill ที่โหลดเข้าบริบท และ Body สั่งให้ทำตาม Skill นั้น |
| **Local** | ไม่ใช้ `skills:` แต่ Body สั่งให้อ่าน `../skills/<name>/SKILL.md` ผ่าน Markdown link แล้วทำตาม Checklist / Template ที่ลิงก์อยู่ใน Skill |

ตัวอย่างจาก `release-auditor.agent.md` (ลิงก์สัมพันธ์กับตำแหน่งไฟล์ Agent):

```markdown
ก่อนเริ่มตรวจ ให้อ่านและทำตาม [Skill release-gate-audit](../skills/release-gate-audit/SKILL.md)
รวมถึงเกณฑ์ตรวจที่ลิงก์ไว้ใน Skill นี้
```

**ผู้เรียน Local ไม่ต้องคัดลอก Skill หรือแก้ `skills:`:** เลือก Agent ที่เตรียมไว้แล้วส่งโจทย์ได้เลย คำสั่งใน Body เป็นการให้โมเดลอ่านไฟล์ ไม่ใช่การเปิดใช้ Frontmatter ที่ Local ไม่รองรับ จึงต้องตรวจหลักฐานการอ่าน Skill / ไฟล์ประกอบตามขั้นตรวจผลลัพธ์ด้านล่าง หากไม่อ่าน ให้แนบ `SKILL.md` ของบทบาทในแชตแล้วส่งว่า **“อ่านและทำตาม Skill ที่แนบก่อนทำโจทย์เดิม”**

อย่าเปลี่ยน `target: github-copilot` เพียงเพื่อซ่อนคำเตือน เพราะ `target` เปลี่ยนการตีความของ Editor ไม่ได้เปลี่ยน Harness ที่รัน

### งานนี้ Skill ก็ทำได้ แล้วเลือก Role Agent เพื่ออะไร?

| สิ่งที่ต้องการ | อยู่ที่ไหน / เหตุผล |
|---|---|
| BA รู้วิธีเขียน Spec, QA รู้วิธีออกแบบเคส, Dev รู้วิธีแก้ตาม Policy | **Skill** เก็บขั้นตอนและแม่แบบ ใช้กับ Default Agent ก็ทำงานเหล่านี้ได้ |
| เลือกบทบาท BA / QA / Dev ที่ทีมเตรียมไว้ ไม่ต้องกำหนดบทบาทใหม่ในทุกแชต | **Agent Body** เก็บหน้าที่และจุดส่งต่องาน; ยังเป็นคำสั่งให้โมเดลทำตาม ไม่ใช่การบังคับ |
| ให้เขียนผลงานได้ แต่ไม่ต้องการ Terminal ในงานนี้ | **Agent `tools:`** ระบุ `read`, `search`, `edit` โดยไม่ระบุ `execute`; ตรวจการกรองจริงในข้อ 4.3 |
| ให้ผู้ตรวจอ่านอย่างเดียว ต่างจากผู้สร้างที่ต้องเขียนไฟล์ | ใช้ **`release-auditor` อีกโปรไฟล์หนึ่ง** ที่ไม่มี `edit` ในรายการ แทนแค่บอกผู้สร้างว่า “เปลี่ยนไปเป็นผู้ตรวจ” ในแชตเดิม |

**ไม่ใช่ทุกบทบาทจำเป็นต้องมี Agent แยก:** BA / QA / Dev ในแล็บนี้มี `tools:` เหมือนกัน ประโยชน์ของการแยกสามตัวคือเลือกหน้าที่และการส่งต่อที่ทีมใช้ซ้ำ ไม่ใช่เพราะ Skill ทำเอกสารหรือแก้โค้ดไม่ได้ ถ้าไม่ต้องการโปรไฟล์เหล่านี้ ใช้ Default Agent + Role Skill ได้

## 3. ทำภารกิจด้วย `Role Agent + Role Skill` (7 นาที)

เปิด **New Chat** → คลิก Agent dropdown แล้วเลือก Agent ประจำสายงานของคุณ (**`ba-analyst`**, **`qa-inspector`** หรือ **`dev-builder`**) แล้วส่งคำขอด้านล่างตามภารกิจที่เลือก:

### สาย BA · เลือก Agent `ba-analyst` (ตรวจการใช้ Skill `cr-spec-writer`)

- **ถ้าเลือก `CR-201` (Project หมูกระทะ):**
  ```text
  ช่วยเขียนเอกสาร Change Request Functional Specification สำหรับ #docs/change-requests/CR-201-booking-deposit.md โดยเปรียบเทียบโค้ดปัจจุบันใน #ui/preview.html กับกฎใน #docs/policies/finance-and-sla-policy.md แล้วบันทึกไฟล์ลงที่ outputs/ba/cr-201-spec.md
  ```
- **ถ้าเลือก `CR-202` (Project ชานมหวานร้อย):**
  ```text
  ช่วยเขียนเอกสาร Change Request Functional Specification สำหรับ #docs/change-requests/CR-202-ecommerce-promo.md โดยเปรียบเทียบโค้ดปัจจุบันใน #ui/preview.html กับกฎใน #docs/policies/finance-and-sla-policy.md แล้วบันทึกไฟล์ลงที่ outputs/ba/cr-202-spec.md
  ```

### สาย QA · เลือก Agent `qa-inspector` (ตรวจการใช้ Skill `test-matrix-designer`)

- **ถ้าเลือก `CR-201` (Project หมูกระทะ):**
  ```text
  ช่วยออกแบบชุดทดสอบ Release Gate Test Matrix (ครบทุกจุดตัด Boundary จำนวนลูกค้า) และบันทึกบั๊กที่พบในโค้ด #ui/preview.html เทียบกับ #docs/policies/finance-and-sla-policy.md สำหรับ #docs/change-requests/CR-201-booking-deposit.md ลงในไฟล์ outputs/qa/cr-201-test-cases.md
  ```
- **ถ้าเลือก `CR-202` (Project ชานมหวานร้อย):**
  ```text
  ช่วยออกแบบชุดทดสอบ Release Gate Test Matrix (ครบเคสซ้อนโค้ด SWEET11 และขอบเขตจำนวนสินค้า) และบันทึกบั๊กที่พบในโค้ด #ui/preview.html เทียบกับ #docs/policies/finance-and-sla-policy.md สำหรับ #docs/change-requests/CR-202-ecommerce-promo.md ลงในไฟล์ outputs/qa/cr-202-test-cases.md
  ```

### สาย Dev · เลือก Agent `dev-builder` (ตรวจการใช้ Skill `ui-implementer`)

- **ถ้าเลือก `CR-201` (Project หมูกระทะ):**
  ```text
  ช่วยแก้ไขโค้ดส่วน Booking App ในไฟล์ #ui/preview.html ให้เป็นไปตามใบงาน #docs/change-requests/CR-201-booking-deposit.md และกฎ BR-01 ถึง BR-03 ใน #docs/policies/finance-and-sla-policy.md ให้ครบทุกข้อ
  ```
- **ถ้าเลือก `CR-202` (Project ชานมหวานร้อย):**
  ```text
  ช่วยแก้ไขโค้ดส่วน E-commerce App ในไฟล์ #ui/preview.html ให้เป็นไปตามใบงาน #docs/change-requests/CR-202-ecommerce-promo.md และกฎ EC-01 ถึง EC-03 ใน #docs/policies/finance-and-sla-policy.md ให้ครบทุกข้อ
  ```

**ตรวจผลลัพธ์ (เทียบกับสไลด์ 5 & 7):**
1. **Skill ทำงานส่วนไหน:** ตรวจรายละเอียดการโหลด / อ่าน `SKILL.md` และไฟล์ประกอบของ Role Skill แล้วชี้ขั้นตอนหรือแม่แบบที่ปรากฏในผลงาน หากหาไม่พบให้บันทึกว่า **ยังยืนยันการใช้ Skill ไม่ได้** และแนบไฟล์ Skill ให้ลองอีกครั้ง อย่าอนุมานจากชื่อ Agent อย่างเดียว
2. **Agent เพิ่มอะไร:** ตรวจบทบาทที่ยังเลือกอยู่และค่า `tools:` แยกจากคุณภาพผลงาน น้ำเสียงและตารางเป็นเพียงผลด้านรูปแบบ ไม่ใช่หลักฐานว่าถอดเครื่องมือสำเร็จ; `STOP` ใน Body ก็ยังต้องตรวจว่าโมเดลทำตามหรือไม่
3. **สำหรับสาย Dev:** เปิดไฟล์ `ui/preview.html` ใน Browser แล้วลองกรอกจำนวนลูกค้า `2, 4, 8, 15` ท่าน (สำหรับ `CR-201`) หรือลองใช้โค้ด `SWEET11` กับโซฟา `Lolito -50%` และกรองหมวด `Lighting` (สำหรับ `CR-202`) เพื่อตรวจว่าแก้บั๊กได้ตรงตามโจทย์
