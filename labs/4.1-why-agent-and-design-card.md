# 4.1 · ทดลองตรวจงานด้วย Agent ที่เตรียมไว้ (8 นาที)

**สิ่งที่จะฝึก:** ตรวจเอกสารเดียวกันด้วย Agent มาตรฐานและ Agent `release-auditor` ที่เตรียมไว้ แล้วเปรียบเทียบผลตรวจและเครื่องมือที่แต่ละตัวใช้ได้ โดยใช้เกณฑ์เดียวกันทั้งสองครั้ง ไม่ต้องออกแบบหรือสร้างไฟล์ใหม่

**โจทย์ของทีม:** ต้องการผู้ตรวจ Release ที่อ่านนโยบายและรายงานข้อผิดพลาดได้ แต่ไม่ต้องการให้มีเครื่องมือแก้ไฟล์หรือรัน Terminal ระหว่างตรวจ การเขียน Checklist ให้ตรวจถูกกับการถอดเครื่องมือออกเป็นคนละเรื่องกัน

---

## 1. ทดลองครั้งที่ 1 · Default Agent + Skill `release-gate-audit` (3 นาที)

ใช้เอกสารร่าง `docs/drafts/sprint2-launch-draft.md` ที่มีตัวเลขและกติกาผิดจาก `docs/policies/finance-and-sla-policy.md`

1. เปิด [Skill `release-gate-audit`](../.github/skills/release-gate-audit/SKILL.md) สังเกตว่ามีทั้งขั้นตอนตรวจ รูปแบบตาราง และข้อความ **ห้ามแก้ไขไฟล์ต้นฉบับ** อยู่แล้ว
2. เปิด **New Chat** → ตั้ง **Session Target เป็น Local** → เลือก **Agent ตัวมาตรฐาน** ใช้ **Manual permissions** และจดชื่อ Model ไว้ ใช้ค่าเดิมทั้งสองครั้ง
3. ส่งคำขอต่อไปนี้ โดยระบุไฟล์ Skill ให้ชัดเจน เพื่อให้ Agent ใช้ขั้นตอนตรวจงานเดียวกับที่จะใช้ในครั้งที่ 2:

```text
ตรวจ #docs/drafts/sprint2-launch-draft.md เทียบกับ #docs/policies/finance-and-sla-policy.md แสดงตาราง Release Gate Audit Findings ในแชต
```

**บันทึกผลจากหลักฐานที่เห็น:**
- เปิดรายละเอียดการทำงาน ดูว่า Agent อ่าน `SKILL.md` และเกณฑ์ตรวจแล้วหรือยัง ถ้ายังไม่ได้อ่าน ให้บันทึกว่ายังนำผลครั้งนี้มาเปรียบเทียบไม่ได้
- ได้ตารางและพบข้อผิดพลาดที่ตรงกับนโยบายหรือไม่? **ถ้าทำได้ แสดงว่า Skill ช่วยตรวจงานได้อยู่แล้ว** ไม่ได้แปลว่าการทดลองล้มเหลว
- เปิดรายการเครื่องมือ ตรวจว่าโมเดลได้รับเครื่องมือแก้ไฟล์หรือ Terminal หรือไม่ จดตามจริง

## 2. ทดลองครั้งที่ 2 · Custom Agent `release-auditor` + Skill เดิม (3 นาที)

1. เปิด [Agent `release-auditor`](../.github/agents/release-auditor.agent.md) ดู `tools: ['read', 'search']` และ Body ที่กำหนดบทบาทผู้ตรวจ
2. เปิด **New Chat** → เลือก **`release-auditor`** ตรวจว่า Harness / Model / Permission mode ตรงกับครั้งที่ 1
3. ส่ง **คำขอเดียวกับครั้งที่ 1 ทุกคำ** แล้วตรวจหลักฐานการอ่าน Skill และรายการเครื่องมือด้วยวิธีเดิม

| สิ่งที่เปรียบเทียบ | ครั้งที่ 1 · Default + Skill | ครั้งที่ 2 · Custom Agent + Skill |
|---|---|---|
| Checklist, เกณฑ์นโยบาย, รูปแบบตาราง | มาจาก `release-gate-audit` | มาจาก **Skill เดิม** |
| บทบาทที่เลือกค้างไว้จนกว่าจะสลับ | Agent มาตรฐาน | `release-auditor` พร้อม Body ประจำบทบาท |
| คำว่า “ห้ามแก้ไฟล์” ใน Prompt / Skill | เป็นคำสั่งให้โมเดลทำตาม (**asks**) | ยังเป็น **asks** เหมือนเดิม |
| เครื่องมือที่ตั้งใจให้ใช้ | ตามการตั้งค่าของ Agent มาตรฐาน | โปรไฟล์ระบุเฉพาะ `read`, `search`; ตรวจผลจริงใน Harness |

**ข้อสรุป:** เราไม่ได้เพิ่ม Custom Agent เพื่อให้ตรวจงานได้เก่งกว่าการใช้ Skill อย่างเดียว แต่เพื่อให้ทีมเลือก **“ผู้ตรวจที่มีชุดเครื่องมือต่างจากผู้ลงมือแก้”** มาใช้ได้ โดยไม่ต้องตั้งค่าบทบาทและเครื่องมือใหม่ทุกครั้ง

> **ขอบเขตการทดลอง:** หาก Agent มาตรฐานในครั้งที่ 1 ถูกจำกัดเครื่องมือไว้แล้ว ทั้งสองครั้งอาจมีเครื่องมือให้ใช้เท่ากันได้ แสดงว่าเราตั้งค่าจำกัดเครื่องมือเองได้เช่นกัน ไม่จำเป็นต้องมี Custom Agent เสมอ หาก Harness เพิ่มเครื่องมือเริ่มต้นแม้ระบุ `tools:` ไว้แล้ว ให้บันทึกความแตกต่างและตรวจต่อในข้อ 4.4 ไม่สรุปว่า “ปลอดภัย 100%” จากไฟล์ตั้งค่าเพียงอย่างเดียว

## 3. อ่านการตั้งค่า Role Agent ที่เตรียมไว้ด้วย Review Card (2 นาที)

1. เปิด [Prepared Agent Review Card](design-card.md) แล้วเลือก **BA**, **QA** หรือ **Dev**
2. เปิดไฟล์ Agent ของบทบาทนั้นคู่กัน อ่านสรุปทั้ง 6 จุดที่กรอกไว้ให้แล้ว
3. ตอบเพียง **2 ข้อท้ายการ์ด:** อะไรยังอยู่ใน Skill และ Agent เพิ่มการตั้งค่าอะไรที่ทีมต้องการ? ยังไม่ต้องแก้ไฟล์ Agent ในขั้นนี้

**เช็กก่อนทำข้อต่อไป**

- [ ] ใช้ Skill เดียวกันและคำขอเดียวกันทั้งสองครั้ง พร้อมบันทึกผลจริงหรือสิ่งที่ยังยืนยันไม่ได้
- [ ] ตอบ 2 ข้อใน [Review Card](design-card.md) สำหรับบทบาทของคุณแล้ว
