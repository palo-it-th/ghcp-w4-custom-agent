# 4.5 · The Whole Ladder Check & Share-out ปิดโปรแกรม (5 นาที)

**สิ่งที่จะฝึก:** สำรวจโครงสร้าง `.github/` ในโปรเจกต์เทียบกับ **บันไดทั้ง 6 ขั้น (The Whole Ladder)** เพื่อทบทวนเนื้อหาจากเวิร์กช็อปทั้ง 4 ครั้ง ว่าข้อมูลแต่ละประเภทถูกส่งให้โมเดลเมื่อใด และกลไกใดบังคับกฎได้จริง

---

## 1. สำรวจไฟล์จริงในโปรเจกต์เทียบกับบันไดทั้ง 6 ขั้น (3 นาที)

ลองเปิดดูโฟลเดอร์ `.github/` และ `.vscode/` ใน Explorer ของโปรเจกต์นี้ คุณจะเห็นว่าเรามีของครบทุกขั้นของบันไดแล้ว:

| ขั้นของบันได | ไฟล์จริงในโปรเจกต์นี้ | ส่งให้โมเดลเมื่อใด? (Reaches the model) | บังคับกฎอย่างไร? (`asks` vs `stops`) |
|---|---|---|---|
| **1. Chat Prompt** | พิมพ์สดในช่อง Chat | ไปเฉพาะครั้งที่พิมพ์ (ไม่ทิ้งไฟล์ไว้) | **Asks** (ขอโมเดลเฉพาะเทิร์นนั้น) |
| **2. Reusable Prompt** | `.github/prompts/quick-cr-check.prompt.md` | เมื่อคุณพิมพ์ `/quick-cr-check` เรียกเอง *(Local harness เท่านั้น)* | **Asks** |
| **3. Repo Instructions** | `.github/copilot-instructions.md` | ติดไปกับ **ทุกคำขอ (Every request)** | **Asks** (และแพ้ Body ของ Custom Agent หากขัดแย้งกัน) |
| **4. Path-scoped Instructions** | `.github/instructions/ui-delivery.instructions.md` (`applyTo: "ui/**,outputs/**"`) | เมื่อ Agent สร้างหรือแก้ไขไฟล์ที่ตรงกับ pattern ใน `applyTo` | **Asks** |
| **5. Agent Skill** | `.github/skills/<name>/SKILL.md` (`cr-spec-writer`, `test-matrix-designer`, `ui-implementer`, `release-gate-audit`) | Body ของ Agent ลิงก์ไปยัง `SKILL.md` และสั่งให้อ่านเนื้อหา / ไฟล์ประกอบก่อนทำงาน | **Asks** (บอกวิธีทำงาน *how to do the work*) |
| **6. Custom Agent** | `.github/agents/<name>.agent.md` (`ba-analyst`, `qa-inspector`, `dev-builder`, `release-auditor`, `broken-helper`) | เมื่อ **คุณเลือก Agent นั้น** จากช่อง Agent dropdown | **Body = Asks** (มีลำดับความสำคัญเหนือ Repo Instructions เมื่อขัดแย้งกัน)<br>**`tools:` = การตั้งค่ากรองเครื่องมือโดย Harness** ต้องตรวจความเข้ากันได้ / default tools ตามข้อ 4.4 |

> **ประโยคสรุปปิดโปรแกรม:**
> - *"Ask in chat once. Repeat it, move it up a step."* (เริ่มจากสั่งในแชต ถ้าต้องสั่งแบบเดิมซ้ำ ให้พิจารณาเก็บเป็นคำสั่งที่ใช้ซ้ำได้ในขั้นถัดไป)
> - *"Rules ask. Tool lists and hooks stop the agent. Required checks stop the merge."* (กฎทั้งหลายแค่ขอร้องโมเดล ส่วนรายการ `tools:` กับ `hooks` หยุด Agent ได้จริง และ Required Check บน PR หยุดการ Merge ได้กับทุกคน)

## 2. เลือกให้พอดีกับงาน แล้ว Share-out (2 นาที)

**ไม่จำเป็นต้องใช้ Custom Agent กับทุกงาน:** เลือกกลไกที่ตอบโจทย์ ไม่ใช่เลือกเพียงเพราะอยู่ในขั้นที่สูงกว่า

| ทีมต้องการอะไร? | เริ่มจากอะไร? | ตัวอย่างในแล็บ |
|---|---|---|
| ขั้นตอน / Template ที่ใช้ซ้ำ โดยไม่เปลี่ยนบทบาทหรือเครื่องมือ | **Skill ก็พอ** | `cr-spec-writer` ช่วยเขียน Spec ได้แม้ใช้ Default Agent |
| บทบาทและชุดเครื่องมือที่เลือกซ้ำได้ | **Custom Agent + Skill** | `release-auditor` ใช้วิธีตรวจเดิม แต่ระบุโปรไฟล์ผู้ตรวจที่ไม่มี `edit` / `execute` ในรายการ |
| งานย่อยที่ต้องการ Context แยก | **Subagent**; ใช้ Custom Agent เมื่ออยากเรียกโปรไฟล์ที่ตั้งชื่อไว้ซ้ำ | ผู้สร้างเรียก `release-auditor` ไปตรวจแล้วรับผลสรุป |
| ห้ามแก้เฉพาะโฟลเดอร์ หรือห้าม Merge การเปลี่ยนแปลงต้องห้าม | **กลไกอนุมัติ / Hook / Required CI ตามโจทย์** ไม่ใช่ Skill หรือ Agent Body อย่างเดียว | `docs/frozen-scope/` ในข้อ 4.4 |

กรอกคำตอบสั้นๆ ท้ายไฟล์ [แบบบันทึกผล (`labs/worksheet.md`)](worksheet.md) เพื่อเตรียมแชร์กับเพื่อนในห้อง 1 ประโยค:
1. **“งาน ___ ใช้ Skill ก็พอ เพราะ ___; จะเพิ่ม Custom Agent เมื่อทีมต้องการ ___”**
2. ถ้าเลือกเพิ่ม Agent คุณจะตั้งค่าบทบาทหรือเครื่องมืออะไร และตรวจอย่างไรว่ามีผลจริง?
