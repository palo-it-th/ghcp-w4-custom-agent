# 4.3 · ส่งงานต่อและแบ่งงานให้ Agent อื่น (10 นาที)

**สิ่งที่จะฝึก:** ใช้ Agent หลายบทบาททำงานกับภารกิจเดียวกัน 2 วิธี

- **Handoff (ส่งงานต่อ):** ให้ Agent ถัดไปรับช่วงทำงานต่อในแชตเดิม
- **Subagent (ผู้ช่วยทำงานย่อย):** ให้ Agent ปัจจุบันมอบหมายงานย่อยให้ Agent อีกตัว แล้วนำผลที่ได้กลับมาประกอบงานหลัก

ตั้ง **Session Target เป็น Local** ก่อนเริ่ม

### เห็นภาพจากงานเดียวกัน: ทำ CR-201

**แบบ Handoff:** BA เขียน Spec เสร็จ → คุณตรวจ Spec → คลิกปุ่มส่งให้ Dev → Dev รับ Spec แล้วแก้โค้ดต่อในแชตเดิม คุณเป็นคนเลือกว่าจะส่งงานเมื่อไร

**แบบ Subagent:** BA เขียน Spec เสร็จ → BA เรียก `release-auditor` มาตรวจ Spec → Auditor ส่งผลตรวจกลับมา → BA สรุปทั้ง Spec และผลตรวจให้คุณ BA ยังคุมงานหลัก ส่วน Auditor ทำเฉพาะงานตรวจใน Context แยก

| ถ้าต้องการ... | ใช้วิธี | สิ่งที่เกิดขึ้น |
|---|---|---|
| ให้บทบาทถัดไปรับช่วงและทำงานต่อ | **Handoff** | Agent ปลายทางเข้ามาทำงานต่อในแชตเดิม หลังคุณคลิกปุ่ม |
| ให้ช่วยตรวจหรือทำงานย่อย โดย Agent เดิมยังคุมงานหลัก | **Subagent** | Agent ที่เรียกยังอยู่ในบทบาทเดิม รับผลสรุปจากงานย่อยกลับมา |

### แล้วเรียก Skill ถัดไปใน Agent เดิมได้ไหม?

ได้ ถ้าต้องการแค่เปลี่ยนวิธีทำงาน แต่ไม่ต้องเปลี่ยนบทบาทหรือเครื่องมือ เช่น ให้ Agent เดิมเปลี่ยนจากเขียน Spec มาออกแบบ Test Matrix

แต่ถ้าต้องการให้ **ผู้ตรวจอ่านอย่างเดียว** ควรใช้ `release-auditor` ซึ่งตั้ง `tools:` ไว้เป็น `read`, `search` และไม่มี `edit` การสั่งให้ Agent ผู้สร้าง “เปลี่ยนไปตรวจ” หรือเปลี่ยน Skill อย่างเดียว **ไม่ได้เปลี่ยนรายการ `tools:`** ทั้งนี้การอ่านค่าจากไฟล์เป็นการตรวจการตั้งค่า ยังไม่ใช่หลักฐานว่าระบบบังคับใช้ข้อจำกัดนั้นจริง

ในแล็บนี้ BA, Dev และ QA มี `tools:` เหมือนกัน การส่งต่อระหว่างสามบทบาทจึงช่วยเลือกหน้าที่และขั้นตอนทำงาน ส่วนการแยกเครื่องมือจะเห็นชัดตอนส่งงานให้ `release-auditor`

## 1. ส่วนที่ 1 · ให้ `release-auditor` ช่วยตรวจในฐานะ Subagent (5 นาที)

ทำส่วนนี้หลัง Role Agent ของคุณ (`ba-analyst`, `qa-inspector` หรือ `dev-builder`) สร้างผลงานแล้ว ในตัวอย่างนี้ Agent เดิมจะขอให้ **`release-auditor`** ตรวจผลงาน โดย Auditor อ่านนโยบาย `docs/policies/finance-and-sla-policy.md` และเกณฑ์ใน Skill `release-gate-audit` ใน Context ของงานตรวจ แล้วส่งผลกลับให้ Agent เดิม

1. เปิดไฟล์ Role Agent ของคุณใน `.github/agents/` (`ba-analyst.agent.md`, `qa-inspector.agent.md` หรือ `dev-builder.agent.md`)
2. เพิ่ม **`'agent'`** ในรายการ `tools:` เพื่อให้ Agent เรียก Subagent ได้ และเพิ่ม **`agents: ['release-auditor']`** เพื่อระบุชื่อ Agent ที่อนุญาตให้เรียก:
   ```yaml
   tools: ['read', 'search', 'edit', 'agent']
   agents: ['release-auditor']
   ```
   *(บันทึกไฟล์หลังแก้เสร็จ)*
3. เปิด **New Chat** → เลือก Role Agent ของคุณ แล้วส่งคำขอให้เรียก `release-auditor` มาตรวจผลงานจากข้อ 4.2 ตัวอย่างเช่น:

   ใน prompt ระบุแค่ว่าจะให้ตรวจไฟล์ไหนก็พอ เพราะ `release-auditor` มีคำสั่งให้อ่าน Policy และใช้ Skill ตรวจงานอยู่แล้ว ไม่ต้องเขียนขั้นตอนเดิมซ้ำ

   - **สำหรับสาย BA (`ba-analyst`):**
     ```text
     ช่วยเรียก release-auditor มาตรวจไฟล์ Spec ของ CR ที่ทำไว้ใน outputs/ba/ แล้วสรุปผลให้ฉันหน่อย
     ```
   - **สำหรับสาย QA (`qa-inspector`):**
     ```text
     ช่วยเรียก release-auditor มาตรวจไฟล์ Test Cases ของ CR ที่ทำไว้ใน outputs/qa/ แล้วสรุปผลให้ฉันหน่อย
     ```
   - **สำหรับสาย Dev (`dev-builder`):**
     ```text
     ช่วยเรียก release-auditor มาตรวจโค้ดที่แก้ไว้ใน ui/preview.html แล้วสรุปผลให้ฉันหน่อย
     ```

**สังเกตสิ่งที่เกิดขึ้น:**
- Agent หลักของคุณยังทำงานอยู่ และมอบหมายงานตรวจให้ `release-auditor`
- Auditor ตรวจใน Context ของงานย่อย แล้วส่งผลกลับมาให้ Agent หลักสรุป
- เปิดรายละเอียด Subagent เพื่อยืนยันว่าเรียก **`release-auditor` จริง** อย่าอาศัยแค่ชื่อที่ปรากฏในคำตอบสรุป หากดูรายละเอียดหรือเครื่องมือที่ใช้ไม่ได้ ให้บันทึกข้อจำกัดนั้น การมี Context แยก **ไม่ได้แปลว่า** ข้อจำกัดเครื่องมือถูกบังคับใช้โดยอัตโนมัติ

## 2. ส่วนที่ 2 · ส่งงานต่อจาก BA ไป Dev และ QA (5 นาที)

คราวนี้ให้ Agent อีกบทบาทรับช่วงทำงานใน **แชตเดิม** ต่างจาก Subagent ตรงที่ Agent ปลายทางจะกลายเป็นผู้ทำงานขั้นถัดไป:

- ในไฟล์ `.github/agents/ba-analyst.agent.md`, `dev-builder.agent.md` และ `qa-inspector.agent.md` เราใส่บล็อก `handoffs:` พร้อม `send: true` ไว้ให้แล้ว:
  ```yaml
  handoffs:
    - label: "Hand off to Dev Builder (ส่ง Spec ให้ Dev แก้โค้ด)"
      agent: dev-builder
      prompt: "จาก BA Change Request Specification ที่เพิ่งเขียนเสร็จ ช่วยใช้ Skill ui-implementer แก้ไขโค้ดใน ui/preview.html..."
      send: true
  ```

### ลองส่งงานต่อใน Local harness
1. เมื่อ `ba-analyst`, `dev-builder` หรือ `qa-inspector` ทำงานเสร็จ จะเห็นปุ่มส่งงานต่อด้านล่างคำตอบ เช่น **`Hand off to Dev Builder`** หรือ **`Hand off to Release Auditor`**
2. คลิกที่ปุ่มนั้น สังเกตว่า:
   - ช่องเลือก Agent สลับไปยัง Agent ปลายทางให้อัตโนมัติ
   - Agent ปลายทางจะได้รับข้อความจาก `prompt:` ทันที เพราะตั้ง `send: true` ไว้
   - ถ้ายังไม่พร้อมให้ Agent ถัดไปเริ่ม อย่าเพิ่งคลิกปุ่ม ให้ตรวจผลงานก่อน แล้วค่อยเลือกว่าจะส่งงานต่อหรือไม่

**จุดที่ควรสังเกต:** เมื่อส่งงานจาก Agent ผู้สร้างไป `release-auditor` บทบาทจะเปลี่ยนจากผู้แก้ไขเป็นผู้ตรวจ และ Agent ปลายทางตั้งค่าไว้ให้ใช้ `read`, `search` โดยไม่มี `edit` ส่วนรูปแบบตารางตรวจมาจาก Skill ได้เหมือนเดิม เพราะ Skill บอกวิธีตรวจ ขณะที่ Agent กำหนดบทบาทและเครื่องมือที่ตั้งค่าไว้
